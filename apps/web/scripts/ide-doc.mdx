The desktop IDE is a fork of [Zed](https://github.com/zed-industries/zed), licensed GPL-3.0-or-later. KnightCode is not affiliated with or endorsed by Zed Industries. The editor is built so KnightCode is its only agent and its only inference path, through a headless engine from this repository.

Packaging lives in the fork, [KnightCodeAI/knightcode-ide](https://github.com/KnightCodeAI/knightcode-ide). The v1 installers are unsigned. Windows SmartScreen and macOS Gatekeeper warn on an unsigned build. A clean-machine install — a machine with no Node, Bun, npm, or CLI — has not been run. The macOS and Linux bundle scripts are written and have not been run.

When a release publishes installers, they are listed on the [download page](/ide).

## What a running IDE is designed to do

Sign in with a provider the CLI already supports: an API key, or an OAuth subscription such as Claude, ChatGPT, or GitHub Copilot. There is no KnightCode account. The IDE and the CLI are designed to read the same `auth.json`, so a machine already signed in to the CLI skips that step.

The editor reaches the engine three ways: the agent panel over ACP, inline assist and commit messages over a loopback chat API, and Tab prediction over a loopback fill-in-the-middle API. One login is supposed to serve all three. That is the exit condition for packaging, and the clean-machine run is still outstanding.

## What it may send

If you allow it on first run, the IDE may send a fixed set of install and launch events: version, channel, operating system, architecture, an approximate location (country, region, city) added by the site, whether setup finished, whether the engine became ready, and which surface you used first. Those events do not include file names, prompts, account details, model ids, or a machine id. `enableInstallTelemetry` turns the set off. `KNIGHTCODE_OFFLINE` suppresses it.

Prompts you send go to the provider you signed in to.

## Bugs

File IDE bugs in [knightcode-ide](https://github.com/KnightCodeAI/knightcode-ide/issues). File bugs in the agent, tools, or providers in [knightcode](https://github.com/KnightCodeAI/knightcode/issues).

When the IDE is running, logs are written to:

- Windows: `%LOCALAPPDATA%\KnightCode\logs\KnightCode.log`
- macOS: `~/Library/Logs/KnightCode/KnightCode.log`
- Linux: `~/.local/share/knightcode/logs/KnightCode.log`

A log can contain file paths, and a path can contain your username. Read it before you paste it into an issue.
